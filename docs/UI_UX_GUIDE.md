# UI/UX デザインガイド（restaurant-management-app から抽出）

> このファイルは、別プロジェクトで同じ見た目・操作感を再現するために、他のAIへそのまま渡すことを想定した仕様書です。
> 「このガイドに厳密に従ってUIを実装してください」と添えて渡してください。

## 1. 技術スタック前提

- React 18 + **MUI (Material UI) v5**（`@mui/material`, `@mui/icons-material`, `@mui/x-date-pickers`）
- スタイルは基本 MUI の `sx` プロップで記述。独自CSSは最小限
- グラフ: recharts / chart.js、カレンダー: react-big-calendar
- 日付: date-fns（ロケール `ja`）
- UI 文言はすべて日本語

※ 別のUIライブラリ（Tailwind / shadcn 等）を使う場合も、以下の色・余白・レイアウト・コンポーネントの役割を同等に再現すること。

## 2. デザイントークン

### テーマ定義（そのまま流用可）

```js
const theme = createTheme({
  palette: {
    primary:   { main: '#4a6da7' },   // 落ち着いたブルー（メインアクション・選択状態・見出しアクセント）
    secondary: { main: '#e57373' },   // ソフトな赤
    background: { default: '#f5f5f5' }, // 薄いグレーの画面背景。カードは白(paper)
  },
  typography: {
    fontFamily: ['"Noto Sans JP"', 'Roboto', '"Helvetica Neue"', 'Arial', 'sans-serif'].join(','),
  },
  components: {
    MuiButton: { styleOverrides: { root: { textTransform: 'none' } } }, // ボタン文字を大文字化しない
  },
});
```

### 意味づけされた色（MUIの標準色を使用）

| 意味 | MUI color | 用途例 |
|---|---|---|
| 主要操作・選択中 | `primary` | 「〜を追加」ボタン、選択中メニュー、調理中 |
| 正常・完了・空き | `success` (#4caf50) | 提供準備完了、空席、在庫十分 |
| 注意・待ち・予約 | `warning` (#ff9800) | 受付待ち、予約済み席、発注リスト |
| エラー・削除・使用中 | `error` (#f44336) | 削除、キャンセル、使用中の席、在庫不足バッジ |
| 補足情報 | `info` | 受付済み |
| 無効・終了 | `default` / `grey.500` | 完了、メンテナンス中 |

補助的な背景色: 強調ボックス `#f5f7fa` + 枠線 `#e1e5eb`（左に 4px の primary 色ライン）、薄い成功 `#e8f5e9`、薄い警告 `#fff8e1`、薄いエラー `#ffebee`、メモ欄 `#f5f5f5` / `#e8f4fd`。

### 余白・形

- MUIの8pxグリッド。ページ内余白 `p: 3`（24px）、モバイルは 16px
- グリッド間隔 `spacing={3}`（ダッシュボード）/ `spacing={2}`（フォーム）
- 見出しとコンテンツの間 `mb: 3`
- 角丸は MUI デフォルト（4px）。小さな情報ボックスは `borderRadius: 1`
- 影: メインカード `Paper elevation={3}`、カード内の小パネル `elevation={1}` + `bgcolor: 'background.default'`

## 3. 全体レイアウト（アプリシェル）

```
┌──────────────┬──────────────────────────────────────────┐
│ 店舗名(太字,  │ AppBar(primary色, fixed)                  │
│ primary色)   │  [≡(モバイルのみ)] 現在のページ名      (Avatar)│
│ レストラン管理│──────────────────────────────────────────│
│ システム      │                                          │
│──────────────│  メインコンテンツ (背景 #f5f5f5, p:3)       │
│ ■基本情報     │                                          │
│  ダッシュボード│                                          │
│  設定         │                                          │
│──────────────│                                          │
│ ■POSシステム  │                                          │
│  …           │                                          │
└──────────────┴──────────────────────────────────────────┘
   幅240px固定
```

- **左サイドバー**: 幅 240px。デスクトップ(`sm`以上)は常時表示（permanent）、モバイルはハンバーガーで開く一時ドロワー（temporary）。メニュー項目タップで自動的に閉じる
- サイドバー上部: 店舗名（h6・太字・primary色）＋ サブタイトル「〇〇管理システム」（body2・text.secondary）
- メニューは **カテゴリ見出し（ListSubheader・太字）でグループ化**し、カテゴリ間に Divider
- 各項目は「アイコン（minWidth 40）＋ラベル」、縦余白は詰め気味（`py: 0.5`）
- **選択中の項目**: 背景 `primary.light`、アイコンと文字は `primary.contrastText`、文字は太字
- **上部AppBar**: サイドバーの右側に固定。左に現在のページ名（メニュー定義から自動取得）、右端にイニシャル入りの Avatar（32px）→ クリックで「設定」「ログアウト」のメニュー
- 未ログイン時は中央にスピナーを出してからログイン画面へリダイレクト

## 4. ページの共通パターン

### 4-1. 一覧・管理ページ（在庫管理、スタッフ管理など大半のページ）

上から順に:

1. **ページヘッダー**: 左にタイトル（`Typography variant="h4" component="h1"`）、右にアクションボタン群
   - 主アクションは `variant="contained"` + `startIcon={<AddIcon />}`（例:「在庫を追加」）
   - 副アクションは `variant="outlined"` + 意味に応じた color、件数があれば `Badge`（color="error"）を付ける
2. **検索・フィルターバー**: `Paper sx={{ p: 2, mb: 3 }}` の中に `Grid` で横並び
   - キーワード検索 `TextField size="small"`（placeholder で検索対象を明示: 「名前、仕入先、保管場所で検索」）
   - カテゴリ・状態の `Select size="small"`、先頭は必ず「すべて」
   - モバイルでは縦積み（`xs={12} sm={4}`）
3. **一覧**: `Table`（`overflow-x: auto` で横スクロール可）。状態は **色付き `Chip`** で表示
4. **作成・編集**: `Dialog` またはページ内の `Paper` フォーム。タイトルは「〇〇を追加」/「〇〇を編集」で切替
   - フォームは `Grid container spacing={2}`、2カラム（`xs={12} sm={6}`）
   - 下部ボタンは右寄せ・間隔16px（キャンセル＝text/outlined、保存＝contained）
5. **フィードバック**: 操作結果は画面下の `Snackbar` + `Alert`（success/error, 6秒で自動消去）

### 4-2. ダッシュボード

- `Container maxWidth="lg"`、ヘッダー右に店舗切替などの `Select`
- 最上段に全幅の情報バー（日付アイコン＋日付、天気などのピル型表示）
- その下を `Grid xs={12} md={6}` の **2列カード** で並べる（売上概要、予約、シフト・タスク、在庫アラート、予実比較グラフなど）。最後に全幅カード
- 各カード: `Paper elevation={3} sx={{ p: 2, height: '100%' }}`、見出しは `h6`
- KPI表示: カード内に小パネル（`elevation={1}`, 背景グレー）を並べ、数値は `h4`、前期比は TrendingUp/Down アイコン＋success/error色
- 読み込み中は中央に `CircularProgress` ＋「データを読み込み中...」、失敗時は `Alert severity="error"`

### 4-3. 現場向け画面（キッチンディスプレイ・フロアマップ・POS）

- **注文カード**: テーブル番号・経過時間をアイコン付きで表示、状態 Chip、`LinearProgress` で進捗（受付待ち5%→受付済20%→調理中60%→完了100%）、ワンタップで次の状態へ進めるボタン
- 状態と色の対応（全画面で統一）:
  - 注文: 受付待ち=warning / 受付済み=info / 調理中=primary / 提供準備完了・提供済み=success / 完了=default / キャンセル=error
  - テーブル: 空席=success / 使用中=error / 予約済=warning / メンテナンス=grey
- フロアマップはテーブルを状態色で塗った図形で配置、クリックで詳細ダイアログ
- 一覧表示とマップ表示は `Tabs` / `ToggleButtonGroup` で切替
- 空状態: 大きなアイコン（60px, text.secondary）＋説明文を中央表示

## 5. UXの原則

- **日本語で具体的なラベル**（「保存」「在庫を追加」「発注リスト」）。ボタンは大文字化しない
- **状態は色＋文字の両方**で伝える（Chip / バッジ）。色だけに頼らない
- **要対応の件数を常に見せる**（Badge で在庫不足件数など）
- 主アクションは各画面1つだけ contained、他は outlined/text
- 破壊的操作（削除）は error 色 + 確認ダイアログ
- すべての非同期処理にローディング表示、結果は Snackbar で通知
- レスポンシブ: `sm`(600px) 未満でサイドバーを隠し、グリッドを1列に。`md`(960px) 未満で POS の2カラムを縦積み
- アイコンは MUI Icons（Filled）で統一し、メニュー・見出し・ボタンに積極的に添える
